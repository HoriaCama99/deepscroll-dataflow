# Deepscroll Dataflow — Portfolio (Implementation Notes)

This document describes the portfolio website located in `lovable/deepscroll-dataflow`:
- what “data” drives the UI (static content/arrays and generated visuals),
- what external files/assets it references,
- and the main animation + UX components.

---

## Tech Stack (as used in this project)

- Frontend: Vite + React + TypeScript
- UI: Tailwind CSS + shadcn-ui (Radix primitives)
- Routing: `react-router-dom`
- Animations:
  - `framer-motion` for scroll/visibility-driven transitions and UI motion
  - `ogl` (WebGL) for the hero “Orb”
  - Canvas 2D for ASCII topography (contact) + footer line animation
  - SVG for the datacube isometric visualization + pipeline diagram

Relevant dependencies (from `package.json`):
- `framer-motion`, `ogl`, `three`/`@react-three/*` (note: this portfolio’s datacube uses SVG, not Three), `tailwindcss`, `@radix-ui/*`, `react-hook-form`, `zod`, etc.

## Page Structure & Navigation

Main sections (with IDs used for navigation):
- `#hero` (`HeroSection`)
- `#datacube` (`DatacubeSection`)
- `#tech` (`TechStackSection`)
- `#clients` (`ClientSection`)
- `#contact` (`ContactSection`)

Navigation UX:
- `SectionNav` is a fixed vertical nav on the right.
- It uses `IntersectionObserver` with rootMargin `-40% 0px -40% 0px` to mark the active section.
- Clicking a button scrolls to the section with `scrollIntoView({ behavior: "smooth" })`.

## “Data” Used by the UI

This site mostly uses static, in-code datasets plus procedural/generated visuals.

### Datacube layer data (static)
File: `src/components/DatacubeScene.tsx`

`LAYERS` drives the isometric “datacube” cube layers:
- Each layer has:
  - `label` (e.g., NDVI, LST, Snow Cover, SAR Regridding)
  - `color` / `accent`
  - `image` (referenced as `/datacube/...` URLs)

### Pipeline steps data (static)
File: `src/components/EoPipelinePanel.tsx`

`STEPS` drives the “System Architecture” pipeline diagram:
- Each step has:
  - `node` id (SVG group id)
  - `conn` connector id(s) (SVG path ids)
  - optional `pkt` packet animation config (id/path/loop speed)
  - `label` and `desc` text content

The pipeline “reveal” is driven by scroll progress (see next sections).

### Clients data (static)
File: `src/components/ClientSection.tsx`

`CLIENTS` drives the “Trusted By” cards:
- name + abbr
- logo path
- description text
- one client supports `logoNoMask` (uses direct `<img>` opacity/mix-blend behavior)

### Tech stack data (static)
File: `src/components/TechStackSection.tsx`

`TECH` drives the grid of `PixelCard` components:
- name + abbr + description
- rendered as animated pixel canvases behind each card’s text

### Contact ASCII topography (procedural)
File: `src/components/ContactSection.tsx`

Instead of external datasets, it generates a topographic ASCII visualization procedurally:
- Noise / fractal helpers:
  - hash/noise3 + fbm-style octave noise
  - contour elevation function
- Rendering:
  - an ASCII character set (`CHARSET = " .:-=+*#%@"`)
  - mouse-driven ripple/distortion in a `requestAnimationFrame` loop

### Background noise visuals (procedural)
File: `src/components/ui/noise-background.tsx`

`NoiseBackground` uses:
- a perimeter-flare palette (`PERIMETER_FLARES`) for colorful radial “flares”
- an inline base64-encoded SVG turbulence/noise data URL
- scroll progress smoothing (`SCROLL_LERP`) to alter flare positions
- optional animated opacity/scale cycling via `framer-motion`

## Animation & UX UI Elements (What the user experiences)

## Hero (top section)
File: `src/components/HeroSection.tsx`
- Hero content fades/slides in via `framer-motion`:
  - intro label
  - main title + subtitle
  - “SPARK / DASK / XARRAY” status line
- Bottom fade gradient blends hero into the next section.
- Scroll indicator:
  - `SCROLL` label
  - a vertical gradient bar animated by `framer-motion` (`y: [0, 8, 0]`, infinite loop)
  - includes reduced-motion handling via CSS `.reduced-motion-hide`

Hero background Orb:
File: `src/components/Orb.tsx` (WebGL via `ogl`)
- Shader-driven orb with:
  - hue shifting
  - noise-based glow variation
  - pointer-hover “inflation” at the cursor
  - optional rotation-on-hover
- Uses device pixel ratio + responsive resizing.

## Mid-page wrapper background
File: `src/components/PortfolioMidSectionWrapper.tsx`
- Wraps the `datacube/tech/clients` sections
- Adds `NoiseBackground` behind the content
- `scrollProgress` is computed from element visibility and smoothed in `NoiseBackground`.

## Datacube + Pipeline (scroll-driven reveal)
Files:
- `src/components/DatacubeSection.tsx`
- `src/components/DatacubeScene.tsx`
- `src/components/EoPipelinePanel.tsx`

Key UX behavior:
- `DatacubeSection` sets a `TOTAL_VH = 700` scroll height and uses `framer-motion`’s `useScroll` on its container to compute `scrollYProgress`.
- The UI changes in defined phases:
  1. Pipeline fullscreen reveal (`0–140vh` normalized)
  2. Slide the pipeline panel into a right-column layout (`140–175vh`)
  3. Collapse pipeline into a compact tab (`175–210vh`)
  4. Activate datacube + right-side layer tabs (`~210vh` through end)

Pipeline panel:
- `EoPipelinePanel` renders an SVG architecture diagram.
- SVG node groups and connectors switch “on” by class toggling as scroll advances.
- Animated “packets” move along SVG paths with:
  - `requestAnimationFrame` for motion
  - `setTimeout` for looping between runs
  - CSS keyframes for glow/shimmer/blink effects

Datacube scene:
- `DatacubeScene` builds the cube geometry procedurally as SVG polygons.
- The “top slab” lifts and crossfades between layers as scroll progresses:
  - unit-square → isometric affine transform used for texture mapping
  - layer textures are referenced via `/datacube/...` image URLs
- Reduced interactivity before the collapse completes:
  - `interactive={isDone}` toggles whether layer hover behavior is enabled.

Right-side layer tabs:
- Appear after the collapse phase
- Highlight the active layer
- Hover updates `hoveredLayer` to preview the corresponding layer state.

## Tech stack grid (interactive pixel cards)
File: `src/components/TechStackSection.tsx`
- Each tech card is a `PixelCard` (canvas-based).
- UX behavior:
  - pixel grid animates “appear” on pointer enter / focus
  - pixel grid animates “disappear” on pointer leave / blur
- Reduced motion support:
  - `prefers-reduced-motion` influences animation pacing and delays.

## Clients cards (expand/collapse details)
File: `src/components/ClientSection.tsx`
- Three client cards in a responsive grid.
- Click a card to expand a description panel:
  - animated height + opacity via `framer-motion`
  - “[-]” / “[+]” indicator in the top-right

## Contact section (ASCII topography + form)
File: `src/components/ContactSection.tsx`
- Background: a full-size ASCII topography canvas.
  - Animated contour lines created via procedural noise
  - Mouse/touch pointer triggers circular ripple effects and local “inflation”
- Contains a form (Name/Email/Message) using shadcn-ui inputs:
  - `Input`, `Textarea`, `Button`, `Label`
- Submit UX:
  - local state `submitted` toggles a success message.

## Footer (interactive canvas line art)
File: `src/components/FooterSection.tsx`
- Canvas draws multiple sine-like horizontal line waves.
- Pointer acts as a “magnet” that bends nearby line points toward the cursor within a radius.
- Scroll progress affects amplitude/frequency (`scrollProgress` alters waveform behavior).

## Accessibility / Motion Considerations

- There’s explicit reduced motion handling:
  - Global reduced motion media query in `src/index.css`
  - Contact, Orb, and some canvas animations check `prefers-reduced-motion` to reduce/eliminate animation
  - Some visuals are hidden when reduced motion is enabled (e.g. `.reduced-motion-hide` for the hero scroll indicator bar)
